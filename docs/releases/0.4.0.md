# Strategy Core V3 0.4.0

Tag `strategy-core-v3-v0.4.0`. Both crates are 0.4.0. This release delivers the hourly
index forecasts and biases of every provider model to bots, including RRFS alongside
HRRR. Model selection and combination remain bot policy.

## Contract change

Decision V6 contexts encoded under 0.3.0 do not decode under 0.4.0; the wire magics and
result format are unchanged. Hosts and Strategy children must move together using the
new immutable release tag, commit, crate archive digest and Decision V6 corpus digest.
Do not mix pins, move a published tag, or reinterpret recorded 0.3.0 contexts as 0.4.0.

- `SuppliedHourlyIndex.forecast` remains the top-level/default HRRR forecast.
- `SuppliedHourlyIndex.forecasts` holds other models' active forecasts, strictly sorted by
  exact model id, with their own bias. Bound: eight non-default models.
- `HourlyIndexComponentsV6.models` holds each other model's separate forecast and bias
  component metadata, strictly sorted by model id, including removal metadata. Active
  forecasts must have matching metadata. Default HRRR must not appear in these lists.
- The kernel projection delivers `HourlyIndexState.forecasts` and
  `HourlyIndexComponents.models` without losing supplied decimals, model identity or
  provenance. `forecast_for(model_id)` and `forecast_components(model_id)` use exact ids
  and never fall back to HRRR.
- Hosts treat `forecasts`/`biases` events as per-model patches and snapshots as the whole
  model set. Empty forecast steps remove that model, including the zero-time default
  placeholder. A removal retains its sequence fence; replayed older events cannot revive
  the forecast or overwrite a newer bias. An absent event map entry changes nothing.

The V6 corpus adds two valid vectors (both models and a removed model) and six invalid
vectors covering duplicate models, missing metadata, invalid bias/time, a duplicated
default model and the model bound. The corpus round-trip and kernel projection prove
that the two models' values, bias and stream revisions stay distinct.

## Use

```toml
strategy-core-kernel = { git = "https://github.com/McFalljb/strategy-core.git", tag = "strategy-core-v3-v0.4.0", version = "=0.4.0" }
strategy-core-v3 = { git = "https://github.com/McFalljb/strategy-core.git", tag = "strategy-core-v3-v0.4.0", version = "=0.4.0", features = ["kernel"] }
```

Follow [the hourly index contract](../decision-v6.md#hourly-index). `current_hour`'s
forecast summary fields are still the provider's HRRR summaries, not RRFS values.

## Publish after merge

```bash
commit=$(git rev-parse origin/main)
git tag -a strategy-core-v3-v0.4.0 -m "Strategy Core V3 0.4.0" "$commit"
git push origin strategy-core-v3-v0.4.0
scripts/pin-digests.sh strategy-core-v3-v0.4.0 > pin-digests.txt
gh release create strategy-core-v3-v0.4.0 --verify-tag \
  --title "Strategy Core V3 0.4.0" --notes-file docs/releases/0.4.0.md \
  conformance/v6/decision-transactions.json conformance/v3/vectors.json pin-digests.txt
```
