# Strategy Core V3 0.2.0

Tag `strategy-core-v3-v0.2.0`. Both crates, `strategy-core-kernel` and `strategy-core-v3`,
are 0.2.0. This release carries everything on `main` since `strategy-core-v3-v0.1.0`. It
breaks 0.1.0 consumers: Decision V5 and the Python packages are gone.

## Use

```toml
[dependencies]
strategy-core-kernel = { git = "https://github.com/McFalljb/strategy-core.git", tag = "strategy-core-v3-v0.2.0", version = "=0.2.0" }
strategy-core-v3 = { git = "https://github.com/McFalljb/strategy-core.git", tag = "strategy-core-v3-v0.2.0", version = "=0.2.0", features = ["kernel"] }
```

Record the tag's commit and digests from `scripts/pin-digests.sh strategy-core-v3-v0.2.0`.
The release's `pin-digests.txt` asset holds the same output.

## Changes since 0.1.0

### Kernel contract (`strategy-core-kernel`)
- A single-run kernel API (`NativeKernel`, `StrategyKernelContext`) over the canonical state
  and event model.
- Timer handles and `cancel_timer`, gauge and annotate telemetry, `ctx.parameters()` and
  `ctx.capabilities()`.
- Station, climate-day and freshness helpers, and exact fee helpers that match the Broker's
  charge and reservation.

### Decision V6 (`strategy-core-v3`)
- The Decision V6 wire, its validation, the runner that presents a context to a kernel, and
  the conformance corpus `conformance/v6/decision-transactions.json`. Decision V5 is
  removed, and so is the V5 checkpoint converter. Decision V4 remains only as V6's owner
  projection.
- Order updates:
  - they survive stale, truncated and reordered views, with bounded tombstones, retried
    updates and complete-view seeding;
  - command ids derive from the IntentId;
  - `BrokerOrderV6` carries `fees_micros` and the provider's rejection text.
- Host-mediated external HTTP and command requests.
- Resident (in-process) native execution over borrowed views.
- Per-order time policy, post-only and a Market buy cap.
- Oracle error distributions (`OracleErrorDistributionV6`) on oracle rows, supplied scores
  and the kernel view. Edges and int64 counts are validated exactly.
- **Event scopes (P1): no station count limit.**
  - `decision_v4::MAX_STATIONS` (5) is removed. The context's byte bound
    (`MAX_DECISION_CONTEXT_V6_BYTES`, checked on encode and decode) is the only limit on
    contributor stations.
  - `examples/decision_v4_schema_max.rs` shows the V4 bound holds 14 schema-maximum stations
    beside 128 schema-maximum markets, and refuses 15. An 8-station event fits.
  - A contributor station may have no data: no observation, report, forecast, oracle table
    or supplied event, only its identity, timezone and climate day. Such a station has the
    empty default oracle table and no current oracle input. Before this release, a context
    with `current_inputs` present rejected it (`InvalidContract`).
  - No struct or wire format changed.

### Repository
- The legacy `strategy-core` crate, the Python packages and the Python V3 release tooling
  are deleted, and CI is Rust-only. A legacy-free gate (`scripts/legacy-free-check.sh`)
  runs in CI.
- Consumers pin a release tag instead of a bare git revision.

## Contract digests

- Decision V6 corpus (`conformance/v6/decision-transactions.json`): the value printed by
  `scripts/pin-digests.sh strategy-core-v3-v0.2.0`. The tag's commit only changes the
  archive digest, not the corpus digest.
- `strategy-core-v3` archive: printed by the same script. It embeds the tagged commit, so it
  is known only once the tag exists.

## Publish (after the release branch merges)

Tag the merge commit on `main`. Never move or reuse the tag: if something is wrong, fix
forward with 0.2.1.

```bash
git fetch origin
commit=$(git rev-parse origin/main)       # the merge commit of the release branch
git tag -a strategy-core-v3-v0.2.0 -m "Strategy Core V3 0.2.0" "$commit"
git push origin strategy-core-v3-v0.2.0
scripts/pin-digests.sh strategy-core-v3-v0.2.0 > pin-digests.txt
gh release create strategy-core-v3-v0.2.0 --verify-tag \
  --title "Strategy Core V3 0.2.0" \
  --notes-file docs/releases/0.2.0.md \
  conformance/v6/decision-transactions.json conformance/v3/vectors.json pin-digests.txt
```
