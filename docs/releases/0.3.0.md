# Strategy Core V3 0.3.0

Tag `strategy-core-v3-v0.3.0`. Both crates, `strategy-core-kernel` and `strategy-core-v3`,
are 0.3.0. This release adds MinuteTemp's hourly Kalshi Weather Index as Strategy host state
(step 2 of `traderv3/docs/plans/2026-09-30-hourly-index-feed-plan.md`), for the hourly
ladder trader. It changes the Decision V6 context wire: contexts encoded by 0.2.0 do not
decode under 0.3.0, and both pinned digests change.

## Use

```toml
[dependencies]
strategy-core-kernel = { git = "https://github.com/McFalljb/strategy-core.git", tag = "strategy-core-v3-v0.3.0", version = "=0.3.0" }
strategy-core-v3 = { git = "https://github.com/McFalljb/strategy-core.git", tag = "strategy-core-v3-v0.3.0", version = "=0.3.0", features = ["kernel"] }
```

Record the tag's commit and digests from `scripts/pin-digests.sh strategy-core-v3-v0.3.0`.
The release's `pin-digests.txt` asset holds the same output.

## Why

The hourly ladder strategy prices Kalshi's hourly temperature ladders from the official
index, its HRRR index forecast and bias, and the feed's health. MinuteTemp computes the
index with Kalshi's calibration and quorum, so the index is a Strategy input delivered by
the host, not something a kernel rebuilds from member observations (this reverses
event-scopes rule 10 for hourly scopes). The kernel reads it on its own timer together with
the books; nothing new triggers a decision.

## Changes since 0.2.0

### Kernel contract (`strategy-core-kernel`)
- `hourly_index` module: `HourlyIndexState` for one index city (`miami`, `nyc`, `chicago`,
  `la-coastal`):
  - identity: `city`, `timezone`, `hourly_series_ticker`, `config_version`,
    `calibration_pending`, and `seq`, the last provider `seq` folded in;
  - `latest`, `latest_valued` and `recent_minutes` (newest first, at most 75): each
    `IndexMinute` has its phase, `is_final`, revision, value/official/provisional values,
    `kalshi_status`, contributors, weight share, quorum, timestamps, provenance and up to 16
    `IndexStationReading`s (temperature, code, source, weight, offset, `pull_f`,
    `change_5m_f`, the hour's member high and low);
  - `current_hour` (`IndexHour`): status, event ticker, `settles_now_as`, high/low,
    `forecast_settle_f`, `forecast_bias_f`, `forecast_adjusted_settle_f`, `final_at`,
    `determine_by` and `feed_conditions` (`FeedConditionKind`, with `Other(name)` for kinds
    this release does not know);
  - `forecast` (`IndexForecast`): model, run and fetch times, missing members, 15-minute
    `steps`, upcoming `settles` and `bias` (with per-member bias);
  - `recent_settlements` (at most 3) and `calibration` (members, quorum);
  - `components`: one `ComponentMeta` per stream (`minutes`, `hour`, `forecast`, `bias`,
    `settlements`, `calibration`).

  Every value has an `f64` convenience beside its supplied original (`Supplied*` with
  `Decimal` numbers and `*_unix_ns` times) and `ValueOrigin::Supplied`. Left out on purpose:
  the ladder and `market_update` (prices come from the Kalshi feed), per-member forecast
  series, the derivable adjusted curve, strike placements and match rates.
- `StrategyKernelState::hourly_index(city) -> Option<&HourlyIndexState>`, with a default
  body returning `None`: hosts and test doubles that do not implement it compile unchanged.
  No `StrategyEventView` variant or trigger kind is added.
- `HOURLY_SERIES_BY_PROFILE` adds the live Weather Index series under `synoptic`:
  `KXTEMPNYCHS` (KLGA), `KXTEMPCHIHS` (KMDW) and `KXTEMPLAXHS` (KLAX), keyed by each index
  city's forecast station. `STATION_TIMEZONES` gains KLGA. The `weather_company` entries
  (`KXTEMPNYCH`, `KXTEMPCHIH`, `KXTEMPLAXH`, …) stay.

### Decision V6 (`strategy-core-v3`)
- `DecisionContextV6` gains a trailing `hourly_index: Option<HourlyIndexInputV6>`
  (`hourly_index_v6`): `{ supplied: SuppliedHourlyIndexV6, components:
  HourlyIndexComponentsV6 }`. The magics stay `SDCTXV6A`/`SDRESV6A`; results are unchanged.
- `HourlyIndexInputV6::validate(decision_time_unix_ms)`, also run by
  `DecisionContextV6::validate` with the context's decision time, checks the city id, each
  component meta (revision and generation ≥ 1), bounds (`BoundExceeded`: 75 minutes, 16
  member readings, 96 forecast steps, 6 settles, 3 settlements, 64 feed conditions),
  orderings (`NonCanonicalOrder`: minutes and settlements newest first, members by station
  id, forecast steps and settles by time), and as `InvalidContract`: aligned forecast
  arrays, canonical decimals, bounded text, `latest`/`latest_valued` agreeing with the
  retained minutes (minute, revision, phase and values), top-of-hour hour ends, and times
  after 2020 and at most 10 minutes (observed, including each component meta's update and
  provenance times), 24 hours (forecast) or 2 hours (current hour) past the decision time.
  Hosts run it before building a context.
- The kernel projection (`KernelSnapshot::from_context`) builds `HourlyIndexState` and
  answers `hourly_index(city)` for the context's city (exact match).
- The hourly index is not part of `decision_fence_v6_sha256`, like the supplied inputs.
- Corpus: valid `hourly-index-snapshot` (a full city at its bounds) and
  `hourly-index-warming` (before the first snapshot); invalid
  `hourly-index-minutes-not-newest-first`, `hourly-index-over-75-minutes`,
  `hourly-index-forecast-arrays-misaligned`, `hourly-index-decimal-over-max-scale`,
  `hourly-index-without-city`, `hourly-index-known-feed-condition-as-other`,
  `hourly-index-component-revision-zero`, `hourly-index-latest-not-newest-retained-minute`,
  `hourly-index-latest-disagrees-with-retained-minute`,
  `hourly-index-component-updated-at-out-of-range`,
  `hourly-index-latest-valued-disagrees-with-retained-minute`,
  `hourly-index-latest-valued-not-newest-valued`, `hourly-index-hour-end-not-top-of-hour`,
  `hourly-index-minute-far-future` and `hourly-index-minute-before-2020` (61 invalid
  vectors).

## For hosts: filling `hourly_index`

Fill it from the scope's `index_city`, folding the city's `hourly_index_snapshot` and its
`seq` events (highest `revision` per minute; `final` never reverts). Leave it `None` for a
scope without an index city. Set each stream's authority as follows:

| Feed state | Authority |
|---|---|
| Subscribed, no snapshot yet | `Warming` |
| Snapshot applied, events applied in `seq` order | `Current` |
| A `resume` in flight (until `resume_complete`) | `RefreshPending` |
| A `seq` gap not yet resumed, or `resume_failed` until the new snapshot | `Uncertain` |
| Unsubscribed, the city rejected, or `subscription_revoked` | `Unavailable` |

Start each meta at revision 1 and generation 1, even while warming. A forecast's `bias` is
`None` when the provider's `bias_f` is null. An unknown phase, status or severity cannot be
represented: mark the stream `Uncertain` rather than guess. See
[Decision V6: Hourly index](../decision-v6.md#hourly-index).

## Re-pin consumers

Both digests change, so every consumer moves together:

- traderv3: `Cargo.toml` (both crates to the tag and `=0.3.0`), `handshake.rs`, `xtask`
  and `deploy/paper-daily/pins.env` (the commit and both digests).
- strategies: `attestation.rs` and `conformance.rs` (the commit and both digests).
- backtester: its strategy-core pin and digests.

Decision contexts recorded under 0.2.0 do not decode under 0.3.0. A consumer that replays
recorded contexts keeps a 0.2.0 decoder for them or re-records.

## Publish (after the release branch merges)

Tag the merge commit on `main`. Never move or reuse the tag: if something is wrong, fix
forward with 0.3.1.

```bash
git fetch origin
commit=$(git rev-parse origin/main)       # the merge commit of the release branch
git tag -a strategy-core-v3-v0.3.0 -m "Strategy Core V3 0.3.0" "$commit"
git push origin strategy-core-v3-v0.3.0
scripts/pin-digests.sh strategy-core-v3-v0.3.0 > pin-digests.txt
gh release create strategy-core-v3-v0.3.0 --verify-tag \
  --title "Strategy Core V3 0.3.0" \
  --notes-file docs/releases/0.3.0.md \
  conformance/v6/decision-transactions.json conformance/v3/vectors.json pin-digests.txt
```
